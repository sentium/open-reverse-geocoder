法務・ライセンス確認メモ（2026年9月7日）

**2026年版への更新で対応したこと**

国内行政界を国土数値情報N03の2026年1月1日時点のデータから再生成した。
取得元・基準日・SHA-256・生成情報は [行政界manifest](../docs/tiles/manifest.json) に記録している。
公開サイトの切替とは別であり、この記録だけで本番が2026年版になったと判断しない。

| 対象 | 今回の整理 |
| --- | --- |
| コード | MIT。データの条件とは区別する |
| 国内行政界2026年版 | 原典のCC BY 4.0表記に従い、出典・ライセンスリンク・加工内容・暫定境界の注意を添付 |
| 国内近傍データ | 国土地理院コンテンツ利用規約・PDL1.0への案内と出典・加工内容を添付 |
| 国外OSMデータ | 既存のODbL 1.0、帰属表示、全量取得経路を維持 |
| 測量法 | 国内行政界の加工・再配布の承認要否と既存承認は未確認。原典の承認番号を本プロジェクトの承認として表示しない |

[2026年版の原典ページ](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html)は、
CC BY 4.0と測量法に関する注意書きの両方を掲載している。
2020年版の「商用可」条件を、そのまま2026年版の条件として引き継ぐものではない。
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.ja)に従い、出典、ライセンス案内、変更した旨等を保持する。
個別の法令・第三者の権利は別途適用される。

配信時の文面：
[国内行政界](../data-licenses/japan-admin.txt)は `tiles/README.txt`、
[国内近傍データ](../data-licenses/japan-nearby.txt)は `data/README.txt` に同梱する。
利用画面の行政界表示例は「国土数値情報『行政区域データ』（国土交通省、2026年版）を加工して作成（CC BY 4.0）」とし、原典・ライセンスへのリンクを付ける。

未完了事項は、国内行政界の測量法上の扱い、実際の利用アプリの帰属表示・プライバシー説明、
バンドルした依存ライブラリの通知の棚卸し、商用運用時のGitHub Pagesの用途適合である。
今回、国土地理院への照会・申請やnpm公開は行っていない。

**以下は更新前の2020年版に対する調査記録**

以下の「現在」「現行」「公開」は main `80a511e` と当時の公開物を指す。
上の更新内容と区別し、2020年版固有の条件・承認番号を2026年版へ転用しない。

対象：main `80a511e`、公開OSMデータ `run-34068352870-1`、国内近傍データ `run-34045813898-1`。
実装・公開ファイルと公式資料を照合した運用上の整理であり、弁護士の法的意見書や各国法への適合保証ではない。

コードとデータのライセンスは別である。コードとOSMデータは条件を守れば商用利用できる。
国内行政界の承認要否と、利用アプリの表示・配信形態には未確認事項があるため、サービス全体について「確認済み」とは扱わない。

| 対象 | 適用条件 | 運用上の扱い |
| --- | --- | --- |
| 自作コード | MIT | 著作権表示と許諾文を保持。アプリのソース公開義務はない |
| OSM13抽出地域の行政界・施設・道路 | ODbL 1.0 | OSMへの帰属表示、ライセンス案内、公開する派生DBの同条件での提供 |
| 国内行政界 `tiles/` | 国土数値情報2020年版の「商用可」条件、旧利用約款準拠版、測量法上の扱い | 出典・加工・利用条件・限界の継承に加え、承認要否と既存承認の確認が必要 |
| 国内近傍データ `data/` | 国土地理院ベクトルタイル提供実験の個別説明と国土地理院コンテンツ利用規約 | 出典・加工表示。現在の一般規約はPDL1.0。提供実験のタイルは基本測量成果ではない |
| npm依存ライブラリ | それぞれのMIT・BSD・ISC等 | バンドルに含むコードも含め、各ライセンスの通知を保持 |
| GitHub Pages | GitHubのサービス利用条件 | データ自体の商用利用許諾とは別に、ホスティング用途の適合を確認 |

コードの根拠は [LICENSE.txt](../LICENSE.txt)。Geolonia Inc.の既存著作権表示を保持する。
国外データの根拠は [OSM copyright](https://www.openstreetmap.org/copyright) と
[ODbL本文](https://opendatacommons.org/licenses/odbl/1-0/)（2.3(a)、3.1、4.2–4.6）。
Geofabrikの公開PBFも [ODbLで配布](https://www.geofabrik.de/data/download.html)されている。
国を追加しても、OSM由来である限りこのデータライセンスの基本は共通である。
これだけで各国の個人情報・地図表示等の法規制まで確認したことにはならない。

**OSMデータの提供者と、利用アプリの役割**

本プロジェクトはカテゴリ抽出・行政界の切り出し・道路幅の推定などを行っているため、配信DBをODbLの派生DBとして扱う。
gzipやタイル分割によってライセンス条件がなくなるわけではない。
現在は各地域の全索引・全タイルを公開し、[全量取得ツール](../bin/download-osm-data.js)を提供している。
公開する派生DBについて、帰属表示・ライセンスの保持と、機械可読な全DBまたは必要な変更情報の提供を維持する。
アプリを非公開ソースで配布することと、OSM由来DBにODbLを適用することは両立する。

利用アプリにもOSMへの帰属表示が必要であり、APIの `attribution` フィールドだけでは利用者への表示は完了しない。
検索結果の近くに短いクレジットを置き、データライセンスの詳細へリンクする方式を推奨する。
全画面・全レコードへの同じ表示を機械的に要求する趣旨ではなく、実際のUIで認識できる表示にする。
根拠：[OSMF帰属表示ガイドライン](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines)のGeocoding・Databasesの項。

走行記録や写真に地名を付けるような個々の逆ジオコーディング結果は、直ちに利用者の全DBをODbLにするものではない。
一方、結果を大量集約して都市以上の範囲の施設DB等を再構成したり、元の検索DBに独自データを統合して公開する場合は別の判断が必要になる。
本APIは地名だけでなく座標・分類・距離等も返すため、地名のみの保存に関する扱いを結果全体へ無条件には拡張しない。
日本と国外は独立したデータとして保持しているが、将来の統合DBについては実際の加工・結合方法を確認する。
根拠：[OSMF Geocoding Guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Geocoding_-_Guideline)。

**国内データで区別が必要な点**

[行政界の生成スクリプト](../bin/build.sh)は `N03-20200101_GML.zip` を指定している。
現行の公開処理は、リポジトリにある既存の行政界タイルをコピーする。2026年の公開処理で2026年版行政界へ更新されたわけではない。
元ZIPの保存・ハッシュによる既存タイルとの厳密な照合までは今回行っていない。

[2020年版の行政区域データ詳細](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-v2_4.html)には、
「商用可」の区分と、国土地理院の複製承認 `R 1JHf 1373` に関する注意書きがある。
これは国の原データ側の承認番号であり、このプロジェクト固有の再配布承認を示すものではない。
[現在の利用規約](https://nlftp.mlit.go.jp/ksj/other/agreement.html)も「商用可」区分を
[旧国土情報利用約款準拠版](https://nlftp.mlit.go.jp/ksj/other/agreement_02.html)へ振り分けている。
したがって、2020年版を一律にMIT・CC BY 4.0・PDL1.0と表記しない。

旧約款は商用の再配布を認める一方、出典・加工表示、個別条件、精度や適用限界の継承を求める。
[国土地理院の手続案内](https://www.gsi.go.jp/LAW/2930-index.html)と
[他者が複製承認を得た成果の利用案内](https://service.gsi.go.jp/onestop/navi/nav4/)に照らし、
全国のポリゴンを加工して公開PBFとして再配布する形態の承認要否を確認する必要がある。
リポジトリ内にはこのプロジェクトの承認書・承認番号を見つけられなかった。承認が存在しないと断定するものではない。
既存の運営者側の記録を確認し、不明なら国土地理院の窓口に利用工程と公開物を示して確認する。
今回、窓口への送信・申請は行っていない。

駅・施設・道路の近傍データは別である。
[提供実験の説明](https://maps.gsi.go.jp/development/vt_expt.html)および
[データ仕様README](https://raw.githubusercontent.com/gsi-cyberjapan/gsimaps-vector-experiment/master/README.md)は、
実験タイルを基本測量成果ではないと明示している。これを理由にN03行政界まで承認不要としない。
利用条件は [国土地理院コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)に従う。
一般規約は2025年11月20日改正でPDL1.0を参照しており、出典と加工した旨を表示する。
商用利用の基本的な許諾は [PDL1.0](https://www.digital.go.jp/resources/open_data/public_data_license_v1.0)で確認できる。
第三者の権利や個別条件まで消えるわけではない。

| OSM manifest | `license: ODbL-1.0`、`licenseUrl`、`attribution`、元PBF URLを確認（公開ファイルはドイツを実査、共通生成コードも確認） |
| OSM全量再取得 | READMEに手順があり、索引から全タイルを列挙する取得ツールがある |
| 国内近傍の `data/README.txt`・manifest | 出典と加工の記載を確認。専用の利用規約URL・ライセンス案内は追加が望ましい |
| 国内行政界の `tiles/README.txt` | HTTP 404。公開処理にも行政界向けの利用条件を添付する処理がない |
| `reverseGeocode` | 国内・国外の出典を返す。実際の利用アプリのUIは今回の確認対象外 |
| npm梱包予定物 | 自作コードの `LICENSE.txt` は含まれる。依存コードをまとめた通知ファイルはない |

公開例：[ドイツのLICENSE.txt](https://sentium.github.io/open-reverse-geocoder/osm/germany/run-34068352870-1/LICENSE.txt)、
[国内近傍データのREADME](https://sentium.github.io/open-reverse-geocoder/data/README.txt)。
Pagesに自作コードのルートLICENSEがないこと自体は、そこでコードを配布していないため直ちに欠落とは扱わない。
国内行政界については、出典・個別条件・精度の限界が配信データと一緒に伝わるようにする必要がある。

`npm ls --omit=dev --all` で確認した通常の実行時依存はMIT・BSD-3-Clause・ISCだった。
これはビルドツールまで含めた全ソフトウェアの監査ではない。
[Rollup設定](../rollup.config.ts)では `fflate` と `axios-cache-adapter` はexternal指定されず、生成JSに含まれる。
`npm pack --dry-run` では両者の個別LICENSEは梱包対象に見当たらず、生成JSでもそれぞれの著作権表示を確認できなかった。
通常のnpm依存として別途インストールされる場合との違いを含め、バンドル配布時の通知を整える必要がある。
次のパッケージ配布前に、実際に含まれる推移依存も棚卸ししてTHIRD_PARTY_NOTICES等を同梱することを推奨する。
この調査ではコード・データの再配布条件を書き換えたり、npmへ公開したりしていない。

**利用画面の表示案**

実際に使用するデータ源に応じて、次の文章から各出典・規約へリンクする。
加工主体がアプリ運営者の場合は、その運営者名も明記する。

- 国外の地名・施設データ：© OpenStreetMap contributors（ODbL 1.0）。open-reverse-geocoderで加工。
- 国内の行政区域：国土数値情報「行政区域データ」（国土交通省）をopen-reverse-geocoderで加工。利用条件は2020年版の個別条件を参照。
- 国内の駅・施設・道路：国土地理院ベクトルタイル提供実験のデータをopen-reverse-geocoderで加工。

詳細画面には、元データ・規約・データ版・取得方法と、地名や施設の収録漏れ、位置・更新時点の限界を記載する。
このAPIの「近傍」や「高速道路上」は推定であり、安全な走行経路・出口への到達可能性を保証する表示にしない。

**配信条件とプライバシー**

[GitHub Pagesの利用制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)は、
商用取引を主目的とするサイトや商用SaaSを提供するための無料ホスティング用途を制限している。
データの商用利用が許可されていても、Pagesを有料アプリの恒常的な配信基盤にできるという保証にはならない。
現在のOSSデータ公開が個別に承認されたことも確認していない。実際の事業用途・利用規模に応じて適合を確認する。
容量と帯域の条件も別途適用される。R2の導入が法律上必要という意味ではない。

ブラウザ利用時の現在の実装は、緯度経度を検索APIへ送る代わりに、タイルを取得して端末内で検索する。
ただし外部通信はあり、配信先にはIPアドレスと地域を推測できるタイルURLが届く。
[GitHub公式の説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)でも、
Pages訪問者のIPをセキュリティ目的で記録するとされている。「第三者への通信・情報送信がない」と説明しない。

走行履歴やアカウントと位置情報を結び付けて収集・分析する場合は、アプリ側の個人情報対応が別途必要になる。
EU向けのサービス提供や行動監視等ではGDPRの適用を確認する。EUの地図データを持つだけで自動的に適用されるとは断定しない。
識別可能な人に関する位置データは個人データになり得る。
根拠：[GDPR第3・4条](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng)。
同意・他の処理根拠、保存期間、削除、委託・越境移転等は実際のアプリのデータフローに応じて評価する。
他の対象国の法令まで今回一括して適合確認したものではない。

**次に対応する順序**

1. 既存国内行政界の出自・承認記録を確認し、加工PBFの公開について測量法上の扱いを確定する。
2. 国内行政界・近傍データの配信フォルダに出典・規約リンク・加工・適用限界の説明を添付する。
3. 利用アプリのOSM/GSI/国土数値情報の帰属表示とプライバシー説明を確認する。
4. 次のライブラリ配布前に、バンドルした依存コードのライセンス通知を整える。
5. 有料サービスの配信基盤として使う場合は、GitHub Pagesの用途制限との適合を確認する。

確認資料にない承認や契約の存在、下流アプリの実装は断定していない。
公開継続・商用運用の最終判断では、特に国内行政界の承認要否を国土地理院の窓口または法務担当者に確認する。
