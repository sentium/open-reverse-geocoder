# 国際逆ジオコーディング（Issue #3）

国内は既存の行政区域データ（国土数値情報）・近傍データ（国土地理院）と `openReverseGeocoder` / `searchNearby` を維持する。
国外は OSM を基準とし、初回の公開対象は米国。次の生成対象として台湾・韓国・インドネシア・インド・ベトナム・フィリピン・タイを追加する。
国の追加によって API を変更しない。公開済みの範囲はカタログを正とする。
機能上の同等性は行政地名・最寄り駅・高速道路施設・名所・距離/優先順位指定を意味し、
OSM に未収録の施設や境界を含む網羅性・位置精度の同一性は保証しない。

## API

`reverseGeocode([longitude, latitude], options)` を追加する。`source` は `auto`
（既定）、`japan`、`osm`。国内の公開済み z10 タイル一覧に含まれる地点だけ既存の
行政界検索を実行し、行政コードが得られた場合は国内として返す。矩形だけで日本と
判定しない。国内データの通信失敗を国外への切り替えで隠さない。

国外は `osmDataUrl/catalog.json` から候補地域を選び、各地域の正確な配信範囲を確認する。
`region` は任意の抽出地域 ID。`nearby` は既存の距離・優先順位・カテゴリ・best/all
オプション、`false` は行政地名のみ。国外の近傍データ URL はカタログで確定した地域を
使う（`nearby.dataUrl` は国内向け）。`japan` は既存の行政界検索オプションを受け取る。

結果は `source`、`countryCode` / `countryName`、`administrativeAreas`、任意の
`nearby`、`dataVersion`、`attribution`。国内は元の戻り値を `japan` に保持し、国外の
`admin_level` と混同しない。国内の階層も国・都道府県・市区町村の順に返すが、
`level` は null とする（コードは国内の都道府県/市区町村コード）。
国外の行政区画は包含するポリゴンを level 順に全て返す。
国によって level の意味が違うため、level 4/6/8 を一律に州/郡/市へ変換しない。
重なった区画は ID 順に返し、近隣の集落から所属自治体を推測しない。

未公開範囲は `UnsupportedRegionError`。公開範囲内の索引にないタイルは既知の空。
掲載ファイルの404・不正データは `SearchDataError`。行政界がない場合は空の階層と
null の国情報を返す。緯度は既存と同じ Web Mercator の範囲（約±85.05°）。

## データ生成

Geofabrik の国別 OSM PBF と index-v1.json の抽出範囲を使用する。
`bin/osm-regions.json` を生成対象と検索検証地点の定義とし、`build-osm-regions.js` が
各地域の抽出ID・国コード・取得URLを照合して順に生成する。米国専用の境界補完は
設定の `boundaryConfig` から呼び出す。台湾は別設定で22県市を確認する。
高雄市のrelationは抽出範囲外の島を含んで欠けていたため、完全なrelationを補完してから
配信範囲で切り抜く。抽出範囲外まで対応範囲を広げない。
`osmium tags-filter` で施設・高速道路・行政境界と参照先を抽出し、`osmium export`
で multipolygon/boundary relation を組み立てる。生成時の PBF SHA-256 とヘッダを保存。
無効で組み立てられない OSM オブジェクトのログも成果物に残す。必要な国境ポリゴンを
欠く場合は、ISO3166-2コードがある所属行政界を結合して国の範囲を導出する。
例えば US-CA の区域内なら米国と判定できる。元の国境relationと区別できる
`osm-derived:country:US` のようなIDを返す。抽出範囲の矩形を国境に転用しない。
導出に必要な所属行政界もなければ、検証で公開を拒否する。
米国では50州とDCのOSM relationを生成前に確認する。欠ける州界や検証地点を包含しない
州界は、OSM APIからそのrelationの完全なメンバーを取得して置き換える。
URL・取得日時・SHA-256を `boundary-sources.json` に、補完後の入力ハッシュも成果物に残す。
この補完は生成時のみで、利用者からOSM APIへは通信しない。PBFと補完した境界の取得時点は
異なり得る。完全なポリゴンを取得できなければ公開を停止する。

Python/Shapely の生成ツールは1地物ずつ処理し、SQLite にタイル単位で一時保存する。
道路は z14、行政界は manifest の `adminZoom`（省略時z8、8〜12）で切り、施設の代表点は z12 に配置する。
台湾・韓国の実データではz8の行政界が16MiBの文字列メモリ上限を超えたため、z10を使用する。
境界の簡略化や上限緩和は行わず、読込・索引の所属検証・全量ダウンロードも同じズームに従う。
既存の米国manifestは `adminZoom` なしのまま読める。新しいズームの地域には対応するライブラリが必要。
穴・飛び地を保持し、日付変更線をまたぐ形状は±180°で分割する。
施設の位置は面内の代表点で、入口・徒歩経路距離ではない。
ID は `osm:{node|way|relation}:{id}` で、同名別施設を統合しない。

駅は station/halt（明示された廃止・貨物専用・private/no access を除く）。
出口は motorway_junction（名称がなければ `Exit {ref}`）、services→sa、rest_area→pa。
国外の分類には attraction / viewpoint / place-of-worship を追加する。
高速道路は motorway 中心線。幅員は width、次いで lanes×3.5m、なければ14mを推定値とする。
国内と同様、中心線距離で走行中を推定し、施設までの直線距離で選ぶ。
同一路線・進行方向・実際に入れる出口/休憩所であることは保証しない。

## 配信と更新

```
osm/catalog.json
osm/{region}/{version}/manifest.json
osm/{region}/{version}/LICENSE.txt
osm/{region}/{version}/index/6/{x}/{y}.json
osm/{region}/{version}/poi/12/{x}/{y}.json
osm/{region}/{version}/road/14/{x}/{y}.json
osm/{region}/{version}/admin/{adminZoom}/{x}/{y}.json
```

v2 manifest は正確な抽出範囲と z6 索引一覧を持つ。全米の細粒度タイル一覧を初回に
転送しない。近傍検索は必要な索引だけを読み、国内と同じキャッシュと4並列制限を使う。
カタログが地域の不変バージョンを指すため、1検索の途中で更新版が混ざらない。

v2では検索半径を覆う矩形が抽出範囲内に入ることを保守的に確認する。穴・細い切れ込みも
検出する。v1の既存データは従来どおりタイル単位で確認する。
隣国のデータを自動結合する機能は初版の対象外。隣国を含めた完全な抽出地域を追加できる。
複数の抽出地域が重なる場合、半径を覆えない地域はスキップして次の地域を試す。
国境情報が欠けて国を確定できない抽出は部分的な結果として保持し、国を確定できる抽出があれば優先する。
いずれの抽出でも国を確定できない場合は最初の部分的な結果を返す。
通信失敗や破損をこの切り替えで隠さない。`region` を明示した場合は指定地域だけを使う。

生成ジョブは国内/国外を別々に実行し、公開許可された成果物を90日保持する。
国外は全対象国の生成・ファイル検証・検索検証が成功した一式だけを `osm-pages-data` にする。
`region` を指定した単独地域の生成と `source_run` による入力再利用はプレビュー専用。
部分更新による既存国の消失を避けるため、公開時は `region=all` かつ新規取得を必須とする。
入力成果物は地域IDごとに分け、各公開版の `provenance/` に取得元・ヘッダ・ハッシュを保存する。
旧形式の米国入力は `region=us` のプレビューに限りルートから読み込める。
初回マージと各生成処理のmainへの変更、手動実行、四半期の定期実行で全国データを生成する。
共通 Pages ワークフローが同一リポジトリの既定ブランチで成功したこれらの実行から
国内・国外の最新成果物を取得し、両方を検証して一括公開する。PR成果物は公開しない。
一方の成果物がない場合は公開を保留し、後続の生成完了時に再判定する。
壊れている場合は検証エラーで停止し、既存サイトを更新しない。
国内の初回全国生成でHTTP 503が発生したため、取得は最大8回の指数バックオフにする。
全国取得の並列数は既存の許容上限8とし、ジョブの330分制限内での完了を目指す。
初回移行では従来の国内 `github-pages` 成果物も読める。

Pagesへ置く検索データ880MB、成果物全体900MBを配信前の上限とし、超える場合は公開を止める。
欧州拡張ではこの上限を超えるため、OSMの実データをR2へ置き、Pagesのカタログから参照する構成を追加した。
[欧州・中南米の範囲と容量](europe-expansion.md)、[R2の設定](r2-publication.md)を参照。
ストレージは自動作成しない。

## ライセンスと検証

OSM由来の配信データは ODbL 1.0 と出典を明示し、各バージョンの全タイルを取得可能にする。
MIT のソースコードと国内の国土数値情報・国土地理院データはそれぞれの利用条件を保持する。
アプリ利用者にも出典表示が必要であることを README に記載する。

単体テスト：分類、幅員、穴、反転した輪郭、日付変更線、範囲外、404、バージョン固定、
優先順位、キャッシュ、国内互換性、タイル境界切断。
結合テスト：実際のワシントンの駅・出口・観光地PBFを変換してHTTP経由で検索する。
この小規模fixtureの行政界だけは合成データ。実米国の行政界は全国生成成果物で別途検証する。

## 追加5か国と圧縮タイル

インドネシア・インド・ベトナム・フィリピン・タイを国別設定へ追加した。
既存3地域と追加5か国の非圧縮データはPagesの配信予算を超えるため、追加5か国の施設・道路・行政界をgzipで保存する。
manifest の `tileCompression: "gzip"` は `.json.gz` を指し、省略時は従来の `.json`。
索引・manifest・カタログは非圧縮のままにし、既存3地域のタイル保存形式を維持する。
生成物の `tileBytes` と検証レポートの `bytes` は実際に保存するファイルのバイト数。

HTTPの自動圧縮とは独立した保存形式で、ライブラリがArrayBufferとして取得・解凍する。
配信側がContent-Encodingで解凍させた場合のJSONバイト列も扱う。
解凍は小さな入力単位で行い、展開量を16MiB以下に制限した上で、従来のJSON文字列メモリ上限も適用する。
CRC32・展開長を照合し、複数gzipメンバー、破損・過大なデータを拒否する。
Node.js 14とブラウザで共通のデコーダを使用し、全量ダウンロードと公開前検証も同じ保存形式を扱う。

インドでは行政界がタイルに辺・点で接する部分から空のMultiPolygonが生成され、全ファイル検証で停止した。
面積のあるポリゴンを含むタイルだけを記録し、接するだけの国境を国の収録実績に数えないよう修正した。
元の行政界形状は簡略化していない。
